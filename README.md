# 1 Adverse Event Summary & Visualization Pipeline

This repository contains clinical programming scripts designed to process CDISC-compliant SDTM and ADaM data and scripts to generate regulatory-grade datasets, tables, and safety visualizations.

## Overview
The pipeline traces patient records from SDTM DS (Disposition) through ADaM ADSL (Subject-Level Analysis) to establish a clean Safety Population. It filters out screen failures, handles missing values safely using base R, ensures unique subject-level counting parameters for adverse events in ADAE, and exports results into validation-ready formats with structured execution logs.

## Data Workflow & Inputs
* **SDTM DS (Disposition)**: Raw domain used to verify patient milestones, screen failures, and study completion status.
* **ADaM ADSL (Subject-Level Analysis)**: The foundational analysis dataset used to define the definitive Safety Population denominators (N) and clean treatment arms (TRT01A).
* **ADaM ADAE (Adverse Events Analysis)**: The source dataset for treatment-emergent adverse event terms (AETERM), system organ classes (AESOC), and severity rankings (AESEV).

## Repository Structure
> **Note**: Each step directory contains its own dedicated `log/` subfolder to hold the corresponding execution logs and audit trails generated by the `{logr}` framework.

*   `question_1_sdtm/` — Directory containing foundational raw data processing scripts.
    *   `01_create_dds_domain.R` — Script to clean, transform, and structure raw disposition data into the SDTM DS domain.
    *   `log/` — Subfolder holding the processing logs for SDTM data generation.
*   `question_2_adam/` — Directory containing clinical analysis dataset programming.
    *   `create_adsl.R` — Script to derive subject-level analysis flags, define the safety population, and generate the ADaM ADSL dataset.
    *   `log/` — Subfolder holding the validation logs for ADaM data derivations.
*   `question_3_tlg/` — Output directory containing table generation scripts, execution logs, and visual assets.
    *   `01_create_ae_summary_table.log` — Automated audit trail and processing log.
    *   `ae_summary_table_nested.html` — Hierarchical HTML summary table.
    *   `ae_severity_bar_chart.png` — 100% stacked bar chart of AE severity.
    *   `ae_severity_heatmap.png` — Matrix grid layout of AE severity counts.
    *   `ae_top_10_incidence_ci.png` — Top 10 AEs with exact 95% Clopper-Pearson CIs.
    *   `log/` — Subfolder holding the formatting and output validation logs.

## Outputs Detail
1.  **Hierarchical Summary Table**: Displays a standalone "Subjects with at least one TEAE" master summary row based on the ADSL safety population denominator, followed by MedDRA Primary System Organ Classes (SOC) and nested Dictionary-Derived Terms (PT) sorted by descending frequency.
2.  **Severity Visuals**: Compares relative proportions (Stacked Bar) and absolute densities (Heatmap Matrix) of MILD, MODERATE, and SEVERE event records across ADSL-defined treatment groups.
3.  **Incidence Rates & CIs**: Estimates individual subject risk percentages alongside Exact Clopper-Pearson 95% Confidence Intervals for the top 10 overall most frequent clinical events, using ADSL arm totals as the analytical baseline.
